# V520 ROCm everyday conversation — CTX4096, three fresh runs

**Verdict:** The four-turn synthetic lunch-planning conversation was **bit-identical across three independent fresh native processes**: prompt/output IDs, rendered replies, natural-stop reasons, committed positions, and complete exported state/KV/facts/canonical bytes all matched. **Behavior was only PARTIAL:** the model remembered the main constraints but recommended generic “seeds/nuts” despite a peanut-avoidance requirement and assumed the rice was pre-cooked to meet the 25-minute limit. Exact repetition of an ambiguous answer is not semantic correctness.

## Scope and method

- Frozen [four-turn request fixture](experiment.json): plan lunch for three using rice/chickpeas/spinach while avoiding peanuts; then adapt to **25 minutes and one pan**; add **dairy avoidance and a small budget**; finally recap the complete plan. Full actual first-run [conversation](transcript.md). Each request sent only the next new user message to the **same live native session** within its run—no history re-PREFILL between turns.
- Three separate managed ROCm server launches, each starting at **position zero**, CTX**4096**, model `gemma-4-26b-a4b-it`, MLX affine-Q4 compatibility `35eeec434dfe1e68d61ffc2a6db88f4738a7ba20ee55967031bded29da967a8a`, binary SHA `3db881c2b312e9bd820b489415e98e14fe44ca8451e288e44001b746edb9d4e4`. T=0 greedy, top-K1, **seed omitted**, DPR off, request proof off, O192 cap. The existing CTX12288 policy parent was **not imported**; it is incompatible with this context geometry and unrelated to this daily-chat fixture. No engine, backend, recipe, or model code changed.
- Effective `rocm` recipe: **W8, NFQ N104/F1/Q4, configured X16**, full HIP intent, 3 decimal-GB expert budget, 1.0 decimal-GB KV budget, and 7.5 decimal-GB all-inclusive RSS ceiling. These are configuration/readiness facts, **not proof that multirow X or any particular GPU kernel engaged**. Native summary mode did not measure phase-aligned GPU compute duty or power. The development checkout at test time was `28774b1740f8c06396bafdbff8693db716240e59` (**2026-09-30T20:05:31-04:00**); source/build identity and actual receipts are in [results.json](results.json).
- After the fourth answer each process made one separately timed `G4KVC006` export, verified its payload digest and canonical header+payload SHA, and stopped normally. The three verified run-owned final artifacts were deleted after exact comparison. No export, serialization, proof scan, or import was on the ordinary four-turn inference path. OS page-cache and host load can differ across repeats.

## Determinism, behavior, and resources

- All three exports ended at position **380**, were **163,430,656 bytes (0.163 decimal GB)**, and had complete-state SHA `f5d27fe769f40c17f266f287a5f83591af50e185a3dc6d998ebdfb809051781b`, facts SHA `7676bdf9e8a08db1b9479d186fb677711f1c15f171f7ac334a095d13c737ea8e`, payload SHA `152810746b587f2f6f02274b4088999f933b8a2c6d722336e7b1c16f92bd491c`, and canonical SHA `01916407cda0a3709e0d6944bbc8b93882a0220d8ca67cde9f9248ac79b4cce6`. Every request was HTTP 200 and `finish_reason=stop`; output IDs and raw text matched turn-by-turn. This proves **same-host, same-build full-state repeatability** for this fixture, not cross-platform identity at CTX4096.
- Full-response review: **turn 1 PASS**—a peanut-free meal using available ingredients. **Turn 2 PARTIAL**—one-pan quick method, but it presumes *pre-cooked* rice although the user only said rice was available. **Turn 3 PARTIAL**—avoids explicit dairy but suggests a generic “seeds/nuts” purchase alongside lemon/tahini, leaving the peanut restriction ambiguous and budget uncertain. **Turn 4 PARTIAL**—recalls the party size, 25 minutes, one pan, the available ingredients, and both dietary restrictions, yet repeats “seeds/nuts” and omits the pre-cooked-rice prerequisite. There was **no explicit recommendation to use peanuts**; the finding is ambiguity and feasibility, not a claim of definite allergen content. The same issues recurred exactly in all three runs.
- Across **24 approximate after-PREFILL/pre-commit snapshots**, maximum current resident and OS peak were **5,648,007,168 bytes (5.648 decimal GB)** under the 7.5-GB ceiling; external-resident category **4,433,391,616 bytes (4.433 GB)**, application **1,228,963,840 bytes (1.229 GB)**, shared **1,075,748,864 bytes (1.076 GB)**, and internal **138,866,688 bytes (0.139 GB)**. Categories are not additive and are **not device-VRAM telemetry**; swap and compressed bytes were reported zero.

**Conclusion:** The ROCm persistent live-KV conversation is deterministic and correctly preserves conversational constraints as state, but its real output quality is **not fully compliant** with the synthetic dietary/time requirements, and decode remains about **291 ms/actual output token** on this four-turn cell. No prompt or runtime change was made to disguise that semantic limitation. The ignored `logs/experiments/rocm-daily-ctx4096-v1/` tree holds exact requests, full responses, native phase metrics, exported-state receipts, and cleanup; no Mac inference was run.
