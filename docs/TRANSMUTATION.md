## Exported conditional proof

[`formal/resource-load-lifecycle/`](formal/resource-load-lifecycle/) contains the model, finite TLC configuration, negative-control configuration, and TLAPS proof. It abstracts one loader invocation each for safetensors, tokenizer, and Gemma pool startup. The source-based request uses `munmap(base, map_len)` on invalid header. Under the external [POSIX `munmap` contract](https://pubs.opengroup.org/onlinepubs/9799919799/functions/munmap.html), a **successful zero return** removes the requested mapping. `OSZeroReturnConditionalRelease` proves that conditional branch in the abstract model; `OSErrorNoPublication` proves only the failed-header/no-publication boundary on an OS error. The C caller does **not** inspect `munmap`'s return, so the outcome is a model input, not a runtime-observed gate. The unconditional-release TLC control deliberately fails on the possible error outcome.

This proof does not demonstrate actual OS reclamation on a particular run, successful cleanup on every branch, complete source correspondence, inference behavior, or tensor/KV byte identity. The exported runtime now contains the later corrected loader source, but source-byte matching is not real serving qualification. The independent bundle check and exact proof-input hashes are in [`FORMAL-PROOFS.md`](FORMAL-PROOFS.md) and [`formal/proof-manifest.json`](formal/proof-manifest.json). No engine-wide proof count or release-readiness claim is promoted by this supplemental module.
